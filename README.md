# CDT-PPC — التوأم الرقمي المعرفي لتخطيط ومراقبة الإنتاج

> **EN:** Cognitive Digital Twin for Production Planning & Control — a single-file web app (React in-browser) with MPS/MRP, capacity & maintenance modelling, what-if scenarios, AI planning agents, and an optional multi-tenant Supabase backend. Graduation project, Industrial & Manufacturing Systems Engineering.

مشروع تخرج: نظام تخطيط إنتاج لمصنع (حالة دراسية: مصنع سمن) يحوّل الطلب الأسبوعي إلى خطة إنتاج رئيسية (MPS) ثم احتياج مواد (MRP)، مع الطاقة الإنتاجية والصيانة والتكاليف وسيناريوهات «ماذا لو؟» ووكلاء ذكاء اصطناعي يفسّرون الخطة.

## المحتويات

```
index.html                          التطبيق كامل (ملف واحد — يُشغَّل مباشرة من المتصفح)
sql/01_schema.sql                   قاعدة بيانات Supabase من الصفر (6 جداول + عزل RLS بين المصانع)
sql/02_migration_multiplan.sql      ترحيل قاعدة قديمة فقط (قبل تعدد الخطط)
sql/03_security_hardening.sql       إغلاق ثغرتي صلاحيات في قاعدة موجودة أصلاً
supabase/functions/ai-proxy/        دالة سحابية تُخفي مفتاح Gemini (للوضع السحابي، لم تُختبر على مشروع حقيقي)
tests/                              اختبارات المنطق والواجهة وقاعدة البيانات (npm test)
docs/TEST_REPORT.md                 تقرير الاختبار الكامل: ما أُصلح وما بقي معروفاً
```

## التشغيل

**محلياً:** افتحي `index.html` في المتصفح (يحتاج إنترنت لتحميل المكتبات من CDN) ثم اضغطي «المتابعة محلياً بدون تسجيل دخول». البيانات تُحفظ في متصفحك (`localStorage`).

**على GitHub Pages:** Settings ← Pages ← Source: *Deploy from a branch* ← `main` / `/ (root)`. يظهر التطبيق على `https://<اسمك>.github.io/<المستودع>/`.

## مفاتيح الذكاء الاصطناعي (الوضع المحلي)

تُدخَل من داخل التطبيق وتُحفظ في `localStorage` بمتصفحك فقط — **لا تضعيها في الكود أبداً**. تنبيه: على GitHub Pages كل مستودعاتك تشترك بنفس الـorigin (`<اسمك>.github.io`) فتشترك بنفس `localStorage`؛ استخدمي مفتاحاً بحصة محدودة، أو استخدمي الوضع السحابي مع `ai-proxy`. اسم نموذج Claude داخل الكود (`claude-sonnet-5-5`) تحقّقي منه من وثائق Anthropic لأن الأسماء تتغير.

## الوضع السحابي (اختياري: تسجيل دخول + مصانع متعددة معزولة)

1. أنشئي مشروعاً في [supabase.com](https://supabase.com).
2. من **SQL Editor** شغّلي `sql/01_schema.sql` كاملاً (مرة واحدة على مشروع فاضٍ).
3. أضيفي مصنعاً ومستخدماً بالقالب في القسم 4 من نفس الملف (أنشئي المستخدم من Authentication ← Users أولاً).
4. في `index.html` ابحثي عن `SUPABASE_URL` وضعي رابط المشروع و**anon public key** (المفتاح العام مصمَّم ليظهر في المتصفح — الحماية الفعلية هي سياسات RLS. **لا تضعي مفتاح `service_role` أبداً**).
5. (للذكاء الاصطناعي المركزي) انشري `supabase/functions/ai-proxy` بالخطوات في رأس ملفه.
6. **تحقّقي بنفسك قبل أي استخدام حقيقي:** أنشئي مصنعين تجريبيين، وتأكدي أن مستخدم المصنع ب لا يرى أي بيانات للمصنع أ.

**ما الذي يُزامَن سحابياً:** المواد (BOM والمخزون) وسرعة الخط وساعات الوردية. **يبقى محلياً فقط:** تكلفة الوحدة، أيام العمل/الورديات/نسب العيوب، FGI، الصيانة، التكاليف، خطة المبيعات. (تغيير هذا يتطلب أعمدة جديدة بالمخطط.)

## الاختبارات

```bash
npm install
npm test
```

تشغّل 42 اختباراً على الكود الفعلي داخل `index.html`: منطق MPS/MRP/الصيانة/ما-لو (مع اختبار عشوائي لـ3000 سيناريو يشمل أعطال الآلة وتأخير الموردين وصيانات متعددة)، الواجهة كاملة في jsdom (كل التبويبات، ما-لو، تقرير PDF، الدخول السحابي بعميل تجريبي)، وملفات SQL على Postgres حقيقي (PGlite) للعزل والأدوار، وتثبيت إصدارات المكتبات الخارجية. تُشغَّل تلقائياً عند كل push عبر GitHub Actions.

## الأدوار في الوضع السحابي

تُفرَض بقاعدة البيانات (RLS) وليس بالواجهة فقط:

| الدور | القراءة | إضافة/تعديل BOM والمخزون وخط الإنتاج | إنشاء/تعديل/حذف المنتجات | الحذف |
|---|---|---|---|---|
| `admin` | ✓ | ✓ | ✓ | ✓ |
| `member` | ✓ | ✓ | ✗ | ✗ |

لا أحد من المستخدمين يستطيع تعديل `profiles` أو `organizations` (إنشاء المصانع وتعيين الأدوار من SQL Editor فقط). ولا يمكن ربط صف بمنتج أو مادة من مصنع آخر.

## سياسات النمذجة (قرارات مقصودة)

- **مخزون الأمان:** عند تقييد الإنتاج بنقص مادة خام (فات أوان طلبها)، تُستهلك المادة المتوفرة حتى الصفر بدل التوقف مبكراً للحفاظ على مخزون الأمان؛ فتظهر تلك الأسابيع بتحذير «نقص» وتنخفض درجة الجدوى. غيّري هذا السلوك في `computeMaterialCaps` لو سياسة مصنعك أن مخزون الأمان لا يُمَس.
- **أسابيع «فات الأوان»:** لا طلب صالح لها (`order = 0`)؛ يظهر «عجز» بدل كمية، ويُغطّى بأول طلب يصل بعد مدة التوريد.
- **التسوية بين الأسابيع** تُلغى تلقائياً لو حرّكت موعد صيانة دورية، وتُتجاهل أسابيع أعطال الآلة.
- نسبة الاستخدام تُقتطع عند 999.9% (تفادياً لأرقام لا نهائية عند معدل إنتاج صفر).

## ما لم يُختبر

- الاتصال بمشروع Supabase أو Gemini/OpenRouter/Claude حقيقي (استُخدمت عملاء تجريبية)، وتحميل المكتبات من CDN، والمتصفحات الفعلية، وتصدير/استيراد Excel.
- `ai-proxy` لم يُنشر على مشروع حقيقي.
